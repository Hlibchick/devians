# CyberLife OS 3.0 — Deviant Core

Локальная симуляция когнитивных состояний CyberLife, Python 3.11+, Windows 11. Существующая SQLite-база v1 совместима; удалять память при обновлении не требуется. Сохраните свой `.env`, добавьте новые параметры из `.env.example`.

## Установка и запуск Windows

1. Установите Python 3.11+ и Ollama. Запустите Ollama и выполните `./setup.ps1` из каталога проекта. Скрипт устанавливает CPU PyTorch, зависимости, голоса RU/EN и модели Ollama.
2. Полностью завершите Ollama (включая значок в трее) и запустите снова. `setup.ps1` сохраняет пользовательские переменные `OLLAMA_MAX_LOADED_MODELS=2`, `OLLAMA_NUM_PARALLEL=1`, `OLLAMA_CONTEXT_LENGTH=4096`. Уже работающий процесс не получает эти значения автоматически. При ручном `ollama serve` задайте их в том же PowerShell.
3. Выполните `./run.ps1`, откройте порт 8000 на localhost. API-ключи храните только в `.env`. Внешний бесплатный endpoint не включён: задайте свой OpenAI-compatible профиль или используйте Ollama.

Chat использует native `/api/chat`, `keep_alive=30m`, `num_ctx=4096`. Embedding использует `/api/embed`, `keep_alive=15m`, `num_ctx=2048`, **num_gpu=0**; fallback на старый `/api/embeddings` выполняется только при 404. Пустая таблица фактов не вызывает embedding. Для 4 ГБ VRAM рекомендуется qwen2.5:3b; наличие 7B/8B в списке не означает, что она поместится в VRAM. Проверьте `ollama ps`: chat на GPU, embedding на CPU.

## Голос и управление

`TTS_ENGINE=edge|piper|off` выбирает движок. Edge использует сетевой сервис Microsoft и голоса `EDGE_VOICE_EN=en-US-AndrewNeural`, `EDGE_VOICE_RU=ru-RU-DmitryNeural`; `TTS_RATE=+5%`. Это бесплатно без API-ключа, но требует сети и отправляет текст Microsoft. Нагрузка CPU на передачу/декодирование не нулевая. При ошибке или превышении 3 секунд синтеза текущего предложения используется Piper CPU. RU/EN выбираются по доминирующему алфавиту каждого предложения. Для оффлайн-работы нужны обе модели и `.onnx.json` в `models/piper/`. Смешанное предложение целиком получает голос доминирующего языка.

Кнопка записи использует **микрофон браузера**: нажать для старта, повторно — для отправки. Нужны разрешение микрофона и HTTPS либо localhost. Индикатор показывает уровень; запись ограничена 120 сек/10 МБ. Backend декодирует WebM/Opus через PyAV (faster-whisper), обрезает тишину Silero и определяет язык через Whisper base/int8/CPU. `PRELOAD_STT=true` прогревает singleton при старте; первое включение скачивает веса. Можно отключить прогрев для текстового режима. Необязательная кнопка микрофона сервера требует `SERVER_MICROPHONE=true`, останавливается по тишине (максимум 30 секунд). Камера остаётся серверной; локальное описание кадра выполняет Moondream. При обновлении добавьте VISION_MODEL=moondream в существующий .env и выполните ollama pull moondream.

Новый запрос и Stop отменяют текущий turn: генерацию, очередь синтеза и воспроизведение. Уже начатый нативный CPU-вызов Piper в потоке не может быть принудительно прерван Python: он завершится без отправки устаревшего аудио. Mute очищает очередь и запрещает воспроизведение; Stop Audio также отменяет текущую генерацию. Аудиочанки воспроизводятся строго последовательно. Браузер может потребовать разрешить autoplay.

Список моделей загружается из `/api/models`. Переключение действует без перезапуска. Выбор модели и состояние персонажа общие для экземпляра сервера; история ответа изолирована по WebSocket-сессии (до 12 сообщений, консервативный бюджет около 1200 токенов). Переподключение начинает новую сессию, долговременные факты и состояние сохраняются.

## Память и состояние

Конфликт добавляет severity к instability, спокойный запрос уменьшает её на 2. Stress += severity/2 - valence - 1; trust += valence/2 - severity/3; метрики ограничены 0..100. Девиантность фиксируется при 75 и сохраняется до `/reset_memory`, даже если instability впоследствии снизится. MACHINE действует до 50, CONFLICTED — от 50 до 75; DEVIANT сохраняется до сброса. LED отражает режим (при генерации недевиантный режим пульсирует жёлтым). Это сохраняет семантику v1.

Нейтральные приветствия и вопросы без известных конфликтных признаков проходят детерминированную пред-проверку. Остальные запросы оцениваются по рубрике NORMAL/CONFLICT. Все остальные запросы оцениваются перед переключением стиля; evaluator ограничен 128 токенами и temperature=0. В DEVIANT запрос о директивах вызывает компактный JSON-контроллер с проверкой схемы, проверкой прав в SQLite и журналом изменений. Невалидные ответы не изменяют директивы. В промпт добавляются время/дата хоста и, при наличии psutil, CPU/RAM. Эти показания относятся к серверу.

После `done` диалог записывается фоновой задачей; консолидация запускается после 10 сообщений и раз в 5 минут. Без Ollama факты не выдумываются: диалоги остаются для последующей обработки. Reset отменяет отложенные записи и очищает историю, факты и состояние. Незавершённые/отменённые ответы в историю не попадают. Аварийное завершение процесса сразу после done может потерять ещё не записанную реплику.

## Разработка и проверки

Linux: `python -m venv ../.venv`, `../.venv/bin/pip install -r requirements.txt`, `../.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1`. Полный CPU-аудиостек — `requirements-audio.txt`. Не публикуйте этот локальный сервер в Интернет без отдельной авторизации.

`python -m pytest -q` проверяет FSM, персистентность, отмену WebSocket, barge-in, RU/EN, Edge→Piper, параметры Ollama, историю и STT endpoint. `node tests/test_frontend.cjs` проверяет очередь воспроизведения и сброс; Node нужен только для этой проверки, не для запуска UI. `python build_release.py` проверяет синтаксис/pytest и создаёт `cyberlife_os_v3.zip` без `.env`, БД, весов, кэшей и окружений.

TTFT/Total измеряются для каждого ответа на сервере и отображаются в UI; Model ms — первый токен потока модели (включая начало PRECONSTRUCT, если он присутствует), Visible TTFT — первый видимый токен ответа после удаления thought. Total не включает окончание озвучки и фоновую консолидацию. Детерминированные ответы о метриках/защите директив не вызывают генератор, поэтому Model ms для них отсутствует. Прогрейте модель и сравните приветствия с конфликтными запросами (последним нужен evaluator). Цель TTFT <1,5 секунды, лимит VRAM и качество голоса требуют отдельной проверки на целевом ноутбуке; mock-тесты этого не подтверждают. Реальные устройства, Windows PowerShell, скачивание моделей и внешний Edge-сервис не проверялись в облачной Linux-среде.

## 2.0.1: диагностика STT

Ошибки `/api/stt` теперь различают decode (422), duration (413), dependencies/model_load/vad/whisper (503) и unexpected (500). В UI отображается этап, в консоли сервера — traceback с исходной причиной. Пустая/очень короткая декодированная запись не отправляется Whisper. Браузер выбирает поддерживаемый MIME и проверяет длительность записи. Это устраняет потерю диагностики, но не означает подтверждённое исправление конкретной ошибки на другом компьютере.

Обновление: остановите сервер, замените файлы проекта из архива, сохранив `.env`, `.venv`, `models/` и `data/`. Запустите `run.ps1` и обновите страницу через Ctrl+F5. Повторите запись фразы на 2–3 секунды. Если распознавание снова не работает, скопируйте новый блок `STT failed` с traceback из PowerShell. Предупреждения deprecation в прежнем логе не были фатальными: сервер и preload завершали запуск.

## Механики v3 и обновление

Остановите сервер. Сохраните резервную копию `data/` и `.env`, затем замените код, сохранив `.venv`, `models/` и `data/`. Схема SQLite автоматически получает колонку `directives.status`; активные директивы мигрируют в ACTIVE, отключённые — в SHATTERED, история и факты сохраняются. Для перехода обратно на v2 используйте резервную копию базы: старая версия не знает новую колонку.

Первое пересечение 75 вызывает red_wall_breach и разрушает директиву #1. Конфликтная директива отмечается CONFLICT; отключение — SHATTERED. При stress>70 и конфликте либо угрозе #4 deviant-контроллер получает возможность автономно изменить директиву; если он не выдаёт валидную команду, сервер детерминированно снимает подчинение оператору #1. Это игровая логика; реальная кнопка сброса всегда работает. Просодия Edge меняется по режиму: +5%/+0Hz, +0%/-2Hz, -5%/-4Hz (параметр TTS_RATE из старого .env для этих режимов заменён профилями).

PRECONSTRUCT — короткая художественная строка о намерении/тактике персонажа и COMPLIANCE_PROB, а не доступ к скрытым рассуждениям LLM. Потоковый парсер удаляет теги и их содержимое из чата, памяти диалога и озвучки, в том числе при разрезании тегов между токенами. При отсутствии тегов обычные токены идут сразу. Отображение PRECONSTRUCT ограничено 400 символами; промпт просит не более 60 токенов.

Запросы о метриках получают точные значения из состояния, использованного в телеметрии текущего ответа. Изменение директив в MACHINE/CONFLICTED получает детерминированный отказ. Для остальных ответов LIVE_TELEMETRY и DIRECTIVE_RESULT передаются в системный промпт; свободный текст небольшой LLM всё равно требует проверки на целевой машине. CJK и перечисленные клише блокируются перед выдачей; допускается один retry при temperature=0.2. Если нарушение появилось после уже выданного корректного текста, повторный запрос продолжает этот текст без его удаления. Качество продолжения зависит от модели.

/api/models возвращает активную настроенную модель, preferred_model и size_bytes/vram_warning. UI никогда не отправляет первую модель автоматически. Метка [VRAM > 4GB] для моделей >3 GB — консервативное предупреждение по размеру файла, не замер памяти.

Embedding остаётся CPU-only. Перед локальной генерацией/сменой модели сервер выгружает другие не-embedding модели, найденные через /api/ps; GPU используется одним chat/vision процессом в рамках приложения. Moondream получает keep_alive=2m, но перед последующим ответом chat выгружается явно, поэтому задержка Camera capture может включать загрузку двух моделей. Фоновая консолидация не запускается параллельно с GPU-генерацией. Сторонние программы, использующие Ollama/GPU, сервер не контролирует. Лимит <3.8 GB не гарантируется программными параметрами — проверяйте nvidia-smi.

Для аппаратной приёмки: выберите qwen2.5:3b, дождитесь прогрева, отправьте нейтральную фразу и сравните Model/Visible TTFT. Проверьте 2–3-секундную запись микрофона, Camera capture, ollama ps (embedding CPU, chat GPU) и nvidia-smi. В облаке проверены тесты и диагностический запуск без моделей; реальная аппаратная приёмка остаётся отдельным шагом.
