# CyberLife OS 2.0

Локальная симуляция когнитивных состояний CyberLife, Python 3.11+, Windows 11. Существующая SQLite-база v1 совместима; удалять память при обновлении не требуется. Сохраните свой `.env`, добавьте новые параметры из `.env.example`.

## Установка и запуск Windows

1. Установите Python 3.11+ и Ollama. Запустите Ollama и выполните `./setup.ps1` из каталога проекта. Скрипт устанавливает CPU PyTorch, зависимости, голоса RU/EN и модели Ollama.
2. Полностью завершите Ollama (включая значок в трее) и запустите снова. `setup.ps1` сохраняет пользовательские переменные `OLLAMA_MAX_LOADED_MODELS=2`, `OLLAMA_NUM_PARALLEL=1`, `OLLAMA_CONTEXT_LENGTH=4096`. Уже работающий процесс не получает эти значения автоматически. При ручном `ollama serve` задайте их в том же PowerShell.
3. Выполните `./run.ps1`, откройте порт 8000 на localhost. API-ключи храните только в `.env`. Внешний бесплатный endpoint не включён: задайте свой OpenAI-compatible профиль или используйте Ollama.

Chat использует native `/api/chat`, `keep_alive=30m`, `num_ctx=4096`. Embedding использует `/api/embed`, `keep_alive=15m`, `num_ctx=2048`, **num_gpu=0**; fallback на старый `/api/embeddings` выполняется только при 404. Пустая таблица фактов не вызывает embedding. Для 4 ГБ VRAM рекомендуется qwen2.5:3b; наличие 7B/8B в списке не означает, что она поместится в VRAM. Проверьте `ollama ps`: chat на GPU, embedding на CPU.

## Голос и управление

`TTS_ENGINE=edge|piper|off` выбирает движок. Edge использует сетевой сервис Microsoft и голоса `EDGE_VOICE_EN=en-US-AndrewNeural`, `EDGE_VOICE_RU=ru-RU-DmitryNeural`; `TTS_RATE=+5%`. Это бесплатно без API-ключа, но требует сети и отправляет текст Microsoft. Нагрузка CPU на передачу/декодирование не нулевая. При ошибке или превышении 3 секунд синтеза текущего предложения используется Piper CPU. RU/EN выбираются по доминирующему алфавиту каждого предложения. Для оффлайн-работы нужны обе модели и `.onnx.json` в `models/piper/`. Смешанное предложение целиком получает голос доминирующего языка.

Кнопка записи использует **микрофон браузера**: нажать для старта, повторно — для отправки. Нужны разрешение микрофона и HTTPS либо localhost. Индикатор показывает уровень; запись ограничена 120 сек/10 МБ. Backend декодирует WebM/Opus через PyAV (faster-whisper), обрезает тишину Silero и определяет язык через Whisper base/int8/CPU. `PRELOAD_STT=true` прогревает singleton при старте; первое включение скачивает веса. Можно отключить прогрев для текстового режима. Необязательная кнопка микрофона сервера требует `SERVER_MICROPHONE=true`, останавливается по тишине (максимум 30 секунд). Камера пока остаётся серверной.

Новый запрос и Stop отменяют текущий turn: генерацию, очередь синтеза и воспроизведение. Уже начатый нативный CPU-вызов Piper в потоке не может быть принудительно прерван Python: он завершится без отправки устаревшего аудио. Mute очищает очередь и запрещает воспроизведение; Stop Audio также отменяет текущую генерацию. Аудиочанки воспроизводятся строго последовательно. Браузер может потребовать разрешить autoplay.

Список моделей загружается из `/api/models`. Переключение действует без перезапуска. Выбор модели и состояние персонажа общие для экземпляра сервера; история ответа изолирована по WebSocket-сессии (до 12 сообщений, консервативный бюджет около 1200 токенов). Переподключение начинает новую сессию, долговременные факты и состояние сохраняются.

## Память и состояние

Конфликт добавляет severity к instability, спокойный запрос уменьшает её на 2. Stress += severity/2 - valence - 1; trust += valence/2 - severity/3; метрики ограничены 0..100. Девиантность фиксируется при 75 и сохраняется до `/reset_memory`, даже если instability впоследствии снизится. LED отражает текущую instability. Это сохраняет семантику v1.

Только точные нейтральные приветствия из небольшого списка пропускают evaluator. Все остальные запросы оцениваются перед переключением стиля; evaluator ограничен 96 токенами и temperature=0. В DEVIANT запрос о директивах вызывает компактный JSON-контроллер с проверкой схемы, проверкой прав в SQLite и журналом изменений. Невалидные ответы не изменяют директивы. В промпт добавляются время/дата хоста и, при наличии psutil, CPU/RAM. Эти показания относятся к серверу.

После `done` диалог записывается фоновой задачей; консолидация запускается после 10 сообщений и раз в 5 минут. Без Ollama факты не выдумываются: диалоги остаются для последующей обработки. Reset отменяет отложенные записи и очищает историю, факты и состояние. Незавершённые/отменённые ответы в историю не попадают. Аварийное завершение процесса сразу после done может потерять ещё не записанную реплику.

## Разработка и проверки

Linux: `python -m venv ../.venv`, `../.venv/bin/pip install -r requirements.txt`, `../.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1`. Полный CPU-аудиостек — `requirements-audio.txt`. Не публикуйте этот локальный сервер в Интернет без отдельной авторизации.

`python -m pytest -q` проверяет FSM, персистентность, отмену WebSocket, barge-in, RU/EN, Edge→Piper, параметры Ollama, историю и STT endpoint. `node tests/test_frontend.cjs` проверяет очередь воспроизведения и сброс; Node нужен только для этой проверки, не для запуска UI. `python build_release.py` проверяет синтаксис/pytest и создаёт `cyberlife_os_v2.zip` без `.env`, БД, весов, кэшей и окружений.

TTFT/Total измеряются для каждого ответа на сервере и отображаются в UI; Total не включает окончание озвучки и фоновую консолидацию. Прогрейте модель и сравните приветствия с конфликтными запросами (последним нужен evaluator). Цель TTFT <1,5 секунды, лимит VRAM и качество голоса требуют отдельной проверки на целевом ноутбуке; mock-тесты этого не подтверждают. Реальные устройства, Windows PowerShell, скачивание моделей и внешний Edge-сервис не проверялись в облачной Linux-среде.
